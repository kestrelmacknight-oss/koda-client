# Koda Client -- Alpha v0.34

A fresh Flutter desktop client, pre-configured for production. Every URL in
this app points at koda.fyi already -- there is nothing to fill in, and
nothing from Fly.io belongs in this project. The client only ever talks to
three public addresses, all already baked into `lib/core/config.dart`:

    https://api.koda.fyi/api/v1   -- REST API
    wss://api.koda.fyi/socket     -- real-time channels (future wiring point)
    wss://voice.koda.fyi          -- LiveKit voice/video

Secrets like DATABASE_URL, GUARDIAN_SECRET_KEY, RESEND_API_KEY, and the
LiveKit API key/secret all live server-side as Fly.io secrets on
koda-server and koda-livekit. None of them are needed here, and none of
them should ever be put in this project.

## Build sequence

This package ships the Dart source only -- the platform-specific Windows
runner files (CMake, C++ scaffolding) are generated by the Flutter SDK
itself, since they need to match your installed Flutter/Visual Studio
version exactly.

### 1. Generate the project skeleton

In an empty folder, with Flutter and Visual Studio's "Desktop development
with C++" workload already installed:

    flutter create --platforms=windows --org com.gryphonheart --project-name koda .

This creates `pubspec.yaml`, `lib/main.dart`, and the `windows/` folder.

### 2. Overwrite with the files from this package

Copy `pubspec.yaml` and the entire `lib/` folder from this package into
that same directory, replacing what `flutter create` generated.

### 3. Fetch dependencies

    flutter pub get

### 4. Build the Windows release

    flutter build windows --release --build-name=0.34.0 --build-number=1

Output lands in `build\windows\x64\runner\Release\` -- confirm `koda.exe`
and a handful of `.dll` files are there before moving on.

### 5. Build the installer

Copy `KodaSetup.nsi` into the same project folder (next to `pubspec.yaml`),
then:

    makensis KodaSetup.nsi

Output: `KodaSetup-Windows.exe`, ready to hand to testers.

## Testing the connection before building an installer

You don't need to package an installer to test against production. From
the project folder:

    flutter run -d windows

This launches a debug build pointed at the real `api.koda.fyi`. Try
registering an account with a real email address -- the verification
code should arrive via Resend within a minute, and you should be able to
log in, create a server, and send a message that round-trips through
Phoenix and ScyllaDB.

## What's intentionally not wired up yet

**Live voice/video media.** Joining a voice channel correctly fetches a
LiveKit token from Phoenix and displays it -- the actual audio/video
connection via the `livekit_client` package is the next piece to wire in.
The token round-trip already proves the server side is correct.

**End-to-end encryption.** `KodaConfig.enableE2EE` is `false`. Messages
currently travel as plain text over TLS (still private in transit, just
not end-to-end encrypted client-to-client yet). The Rust `koda_protocol`
crate from earlier sessions is the wiring point for this when you're
ready to bring it back in.

**Real-time push.** Messages currently load on channel open and on send --
there's no live socket subscription yet, so a second person's message
won't appear until you reopen the channel. `wss://api.koda.fyi/socket`
is reachable and the Phoenix channel exists server-side; the Flutter
side needs the `phoenix_socket` (or similar) package wired into
`home_screen.dart` to subscribe.

None of these gaps affect the parts already in this build -- registration,
login, email verification, password reset, the forced password change
flow for admin accounts, server/channel creation, sending messages, and
all legal/contact links pointing at koda.fyi are complete and functional
against your live Fly.io backend today.
